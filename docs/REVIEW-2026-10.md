# Code review, October 2026

**What this is.** Before version 1.3.1 was published, the whole codebase (commit `877a56d`) was
reviewed line by line by a second AI model, different from the one that wrote it. Six focused
passes each read one area end to end — the atomic swap engine; the Market (Nostr order board)
and its WebSocket transport; the wallet core (keys, transactions, sync, SPV, encrypted storage);
the desktop and Android platform layers; the services layer and user interface; mining and proof
of work — and every finding rated high or above was re-verified against the code, several by
running a proof of concept. Dependencies, the pinning of the bundled node's source and the CI
workflows were checked separately.

**What this is not.** It is not an independent security audit by human experts, and it proves
nothing about the absence of bugs. It found real problems — one serious — which is exactly why an
audit is still needed before anyone should trust this wallet with meaningful amounts. Use small
amounts and read the [disclaimer](../DISCLAIMER.md).

## Summary

The cryptography, key derivation, transaction signing, contract scripts, encryption at rest and
the platform hardening matched their references (lbry-sdk's vectors, lbcd's source, Decred's
atomic swap script, the NIP-44 vectors). The serious problem was in what the wallet trusted about
the LBC chain: a hub server could make a non-existent transaction look confirmed, and the swap
engine relied on that before coins moved. Next to it: a 10×-style amount-entry bug for users
whose keyboards use a decimal comma, and several state-machine gaps in swaps and the Market where
an honest user's coins could get stuck for a day or two. Nothing had been published when the
review ran; the fixes below are part of 1.3.1.

## Findings and status

Severity: **C** critical, **H** high, **M** medium, **L** low.

| # | Sev. | Finding | Status in 1.3.1 |
| --- | --- | --- | --- |
| 1 | C | LBC confirmations were verified against a single block header (merkle proof and the header's own proof of work) with no link to the real chain and a tip taken on the hub's word. A hub, or anyone on the plain-text hub connection, could forge a "confirmed" payment in seconds; the swap engine trusted this before locking Bitcoin or revealing the secret. | **Fixed for swaps:** every announced tip must carry valid proof of work; a funding payment passes only with a merkle proof, a run of headers from the payment to the tip that links and obeys LBRY's difficulty rule (ported from lbcd), and a second hub's agreement on the payment's block and the twelve after it. A single configured hub is taken at its word with a warning; your own node checks itself. **Open for the wallet's display:** ordinary confirmation counts still come from the hub (now stated plainly in SECURITY.md). A validated header chain since a checkpoint is the planned foundation. |
| 2 | H | A decimal comma was stripped as a thousands separator: "12,5" sent 125 LBC, "0,001" BTC became 1 BTC; Persian, Arabic and Hindi digits were dropped. | **Fixed:** the parser understands decimal commas, grouped digits in both conventions, those scripts' digits and the Arabic decimal sign; ambiguous input like "1,000" is refused rather than guessed. |
| 3 | H | Only the first reported spend of a swap contract was examined, so one lying Bitcoin explorer could hide the other side's claim (and the secret in it); the starter lost. | **Fixed:** every reported spend is examined. |
| 4 | H | A maker that had been offline gave up on a taker by wall clock and then ignored the taker's lock code: the taker's coins stayed locked for 48 hours. | **Fixed:** the maker gives up only once the relays have delivered everything they hold, with a relay connected; sleep is detected. |
| 5 | H | Unlock had no re-entrancy guard: a held Enter key started several unlocks, orphaned sync engines with keys in memory and several 128 MB key derivations at once. | **Fixed:** unlock and lock are serialised in the service; the unlock, send and password forms ignore repeated submits. |
| 6 | M | Every swap step depended on the first Bitcoin explorer answering. | **Fixed:** tip and fee come from whichever explorers answer (median fee); the last known tip is kept. |
| 7 | M | The Bitcoin fee rate was taken from the explorer unbounded; a wrong estimate could burn most of a claim. | **Fixed:** bounded to 1,000 sat/vB and a quarter of the amount. Fee bumping of a stuck claim is not implemented yet. |
| 8 | M | A second payment into a swap contract (a "top-up") was never refunded. | **Open** (documented: pay into a contract once). |
| 9 | M | The default 15-minute inactivity auto-lock silently stopped running swaps. | **Fixed:** the inactivity lock waits while a swap runs; manual, sleep and screen locks are unchanged. |
| 10 | M | Swap contract details were written to disk after the funding payment was broadcast; a crash in that window could lose the contract's lock time, and the wallet recorded its own broadcasts only after the server accepted them. | **Fixed:** the contract is flushed before paying; a broadcast is recorded before it is sent and forgotten again if refused. |
| 11 | M | Trade messages that arrived while the wallet was locked were consumed and never asked for again. | **Fixed:** the message subscription is dropped on lock and renewed on unlock, so relays resend. |
| 12 | M | "Send max" and "unlock supports" with hundreds of small coins built a transaction the network refuses. | **Fixed:** at most 600 coins per transaction (the largest ones for "send max"); a fixed amount needing more is refused with a clear message. |
| 13 | M | Turning "ask for the password on every send" off after unlocking broke sending until the next re-lock. | **Fixed.** |
| 14 | M | The miner followed a pool's `client.reconnect` to any host, taking its login with it. | **Fixed:** only a port change on the configured host is accepted. |
| 15 | M | `mining.set_difficulty` was unbounded: an absurd value flooded submits until the miner ran out of memory, or stopped work for good. | **Fixed:** bounded, with a cap on in-flight shares; malformed lines no longer crash the connection. |
| 16 | M | The renderer could make the main process open an arbitrary path (needs a compromised renderer); the UI is served from `file://`, where a compromised page could read local files; ASAR integrity does not cover the unpacked main-process code; stopping the node falls back to an immediate hard kill if one RPC call fails. | **Open** — defence in depth, planned for the next release. |
| 17 | L | Restore falls back to BIP44 when the hub scan fails (about 1 in 16 LBRY Desktop phrases also pass the BIP39 checksum); key material not wiped after some derivations; the `.bak` wallet file keeps the old password's sealed secret until the next write; the hub's network is not checked; price staleness not shown; server error strings shown as the wallet's own; RPC credentials on the node's command line; a few Android socket edge cases; solo mining ignores longpoll. | **Open**, with two exceptions fixed in 1.3.0: a transaction the network already had is no longer reported as a failed send, and a state write at lock time is no longer skipped. |

## Checked and found correct

Listed so the coverage is visible, not as proof of absence of bugs.

- **Keys and derivation:** BIP39 and the LBRY/Odysee scheme reproduce lbry-sdk's vectors; gap
  discovery never issues beyond the gap.
- **Addresses:** version bytes and bech32 per network; wrong-network, mixed-case, zero-width and
  bidi input rejected on every send path.
- **Transactions:** legacy `SIGHASH_ALL` with the full claim-prefixed script as `scriptCode`
  (matches lbcd), RFC 6979 low-S signatures re-verified before broadcast, lbcd's fee floor and a
  dust limit above its own, claims never spent, supports only on explicit unlock.
- **Storage:** scrypt (N = 2¹⁷) → AES-256-GCM with a fresh nonce per seal; both the secret and the
  state (history, contacts, swap and Market keys) encrypted; temp + fsync + rename on both
  platforms; no cloud backup on Android.
- **Swap contract:** byte-exact Decred HTLC, `OP_SIZE 32` on the secret, P2SH on both chains,
  correct lock-time windows and refund timing, codes with checksums and size limits bound to a
  swap.
- **Market:** NIP-44 v2 matches the specification and vectors; every relay event is verified and
  matched against the subscription's own filters; amounts and prices enforced; the taker joins
  only an invite with exactly the amounts it took; takes serialised; the terms gate enforced in
  the service.
- **Transport:** TLS with certificate and host-name verification on desktop (also through SOCKS5,
  with proxy-side name resolution) and Android; frame and message size caps; no header injection.
- **Desktop and Android hardening:** sandbox, context isolation, strict CSP, navigation and
  permissions blocked, every IPC argument validated, `openExternal` restricted to `https:`;
  lbcd spawned without a shell on loopback with fresh credentials; secret screens blocked from
  screenshots.
- **Mining:** the proof-of-work chain matches lbcd exactly in TypeScript and in both WebAssembly
  builds; the Stratum variant matches yiimp's LBRY implementation; solo block construction
  matches lbcd; the subsidy schedule sums to 1,083,202,000 LBC.
- **Supply chain:** the only runtime dependencies are the `@noble` and `@scure` libraries at
  exact versions with no known vulnerabilities; `lbcd` and `btcd` are built from sources pinned
  by their Go module checksums; CI runs read-only, and the mainnet test secret is exposed only to
  manual runs.

## What an audit should start with

1. The header-chain foundation (finding 1): a validated chain since a checkpoint, used for every
   confirmation, with LBRY's retarget rule and checkpoints maintained in the repository.
2. The swap engine's state machine against adversarial servers and clocks, and the Market's
   state machine against hostile relays and counterparties; both have fake-server unit tests now,
   but the Market still has few.
3. The platform items in finding 16.
4. Everything this review did not run live: no share was ever submitted to a real pool, and no
   swap has run on the real networks.

Report security problems privately: a private security advisory on the GitHub repository, never a
public issue, and never with anyone's recovery phrase, password or keys.
